## 2. Team endpoints

Routes are in `/Users/anshumanbiswas/play/taskai/api/cmd/api/main.go:608-625`, all behind JWTAuth. The public token lookup is at `:429`. Handlers are in `/Users/anshumanbiswas/play/taskai/api/internal/api/team_handlers.go`, and most use ent rather than raw SQL.

**How the "current team" is chosen**
- `getUserTeamID` (`team_handlers.go:985-996`) runs `TeamMember.Query().Where(user_id=X, status='active').First(ctx)`. **There is no ORDER BY**, so a user in more than one team gets whichever row the database returns first. There is no stored "current team" and no team switcher.
- `getUserTeamRole` (`:998-1010`) returns the user's role in that team.
- Every user gets their own team as owner at signup: `auth_handlers.go:143-170` for password signup, `internal/db/oauth_store.go:157-178` for OAuth. So everyone owns one team and can join more.
- Accepting a team invite adds a second `team_members` row. From then on, "my team" can resolve to either team.

**Why a user sees everyone:**
- In Settings, `GET /team/members` shows the roster of the team `getUserTeamID` picks. If the user has joined a big shared team (say an org owner invited everybody), the unordered `First()` can return that team, and they see its whole roster.
- In the project picker, `/me/collaborators` returns the union of every team the user belongs to. One all-hands team makes every user a collaborator of every other user.
- Team search is global, and add-member doesn't ask the other person. So any user can pull anyone into their team, and after that the shared-team check that guards project invites passes.

- Admin force-accept: `admin_handlers.go:807`, route `/admin/team-invitations/{id}/resolve`.

## 3. Projects and teams, and the "add member" flow

**Creating a project** (`project_handlers.go:111-170`): sets `team_id = getUserTeamID(...)`, which inherits the nondeterminism, and inserts the creator into `project_members` as 'owner'.

**How much `team_id` is used:** very little. Project access goes entirely through `project_members`:
- `userHasProjectAccess` at `project_settings_handlers.go:543`
- `checkProjectAccess` at `task_handlers.go:1505`

The only place that reads `projects.team_id` is GitHub user auto-matching, `github_handlers.go:945-951`.

The project-member handlers are in `/Users/anshumanbiswas/play/taskai/api/internal/api/project_settings_handlers.go`, with routes at `main.go:566-590`:
- **GET `/projects/{id}/members`** (:71): project members joined to users. Requires project access.
- **POST `/projects/{id}/members`** (:126): the legacy direct add by email. Requires project owner or admin, and that the two users share an active team (:189-208). Then inserts into `project_members`.
- **POST `/projects/{id}/invitations`** (:617): the flow the UI uses. It:
  - requires project owner or admin (:630),
  - rejects the project owner as invitee,
  - applies the same shared-team EXISTS check (:676-694),
  - rejects existing members,
  - upserts `project_invitations` with ON CONFLICT → pending (:711),
  - sends an email and a websocket `project_invitation` event.
- **Accepting** (`/project-invitations/{id}/accept`, :822): the invitee id must match. In one transaction it sets status accepted and inserts into `project_members` (ON CONFLICT DO NOTHING), then broadcasts `project_membership`.
- Also: reject :908, withdraw :953, resend (48h cooldown) :999, `/my/project-invitations` :1080, count :1132.

One quirk: `userIsProjectOwnerOrAdmin` (:568-590) checks `role == "admin"`. The valid project roles are viewer, member, editor and owner, so a project member with role 'owner' who isn't `projects.owner_id` is not treated as an admin.

**Which users the "add member" picker shows:** `ProjectSettings.tsx:185-190` calls `getCollaborators()`, i.e. `/api/me/collaborators`, which covers every team you share. It filters out existing members and pending invitees at :554-557 and renders a `SearchSelect` at :700-738. So yes, it lists members of all your teams, not just the project's team. This comes from commit a2a0325 ("fix: allow cross-team project member invites").
